# Cartograph v2.1.21

Cartograph v2.1.21 stops failed automatic indexing from building a generation backlog, speeds backlog pruning, and moves to ParadeDB 0.25.3.

## Changes

- Five unresolved capacity failures trip a circuit breaker that suspends automatic indexing even as the source keeps changing; each failed attempt runs bounded retention first (#142).
- `cartograph serve --mcp --no-auto-sync` disables filesystem watching and periodic reconciliation for an operator-controlled recovery host.
- `db prune --maximum-deletions` can remove up to 10,000 relation-free failed generations per batch instead of being silently capped at 64.
- Lease heartbeats tolerate backward host clock adjustments instead of failing a PostgreSQL constraint.
- Managed, development, and CI image is ParadeDB 0.25.3; capability checks and managed upgrades require `pg_search` 0.25.3 (dependency update from PR #141).

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH> --json`. If it requests a managed database replacement, take the requested backup, use the exact confirmation phrase, and rerun the same command until `completed: true`.

**Compatibility:** schema 38 (unchanged) · contract V14 (unchanged) · `pg_search` 0.25.3 · managed image pgvector 0.8.4; existing `bm25` relations stay compatible.

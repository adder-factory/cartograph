# Cartograph v2.1.44

Cartograph v2.1.44 makes retention continue on idle hosts and keeps automatic indexing from outrunning cleanup.

## Changes

- Periodic generation and parse-cache cleanup runs alongside the watcher event loop under its supervised lifetime, including when source is unchanged or automatic indexing is suppressed. Maintenance failures back off independently from 30 seconds to 15 minutes.
- Automatic indexing counts eligible failed, retiring, and excess superseded generations before reserving more work. An unresolved drain returns retryable `retention_backlog`, including when cleanup makes no progress; competing project leases retain `lease_busy` handling. Explicit indexing remains available.
- Interrupted retention reports name the fixed phase and allowlisted relation while preserving previously committed batches. Current generations, two recent superseded generations, active leases, and incomplete imports remain protected.
- `autoSync` status reports maintenance attempts, consecutive failures, and the next maintenance time independently of source/index retries.
- Git dirtiness checks and local-backend process probes use bounded async subprocess handling. Missing process observations remain unavailable and cannot authorize backend replacement or signalling. See the [async execution review](https://github.com/adder-factory/cartograph/blob/main/docs/v2/ASYNC-REVIEW-2026-10-13.md).

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>` and require `completed: true`. Reopen attached MCP hosts to activate the new background owner. Existing physical database allocation can still require bounded explicit pruning or online compaction; ordinary retention preserves reusable heap space.

**Compatibility:** schema 50 (unchanged) · contract V23 (unchanged) · external PostgreSQL 18.4+ (major 18), `pg_search` 0.26.1, pgvector 0.8.4+ (0.8.7 recommended); managed uses pgvector 0.8.6. PostgreSQL and extensions remain separate services.

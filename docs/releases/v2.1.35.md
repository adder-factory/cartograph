# Cartograph v2.1.35

Cartograph v2.1.35 fixes a rare hang of CLI admin index jobs and keeps index
lease heartbeats running through long CPU-bound stages. It reports contention
with another writer as `lease_busy` instead of a cleanup failure, and keeps a
failure's primary code when cleanup also fails. Index failure reports now read
`previous_generation_visible` from PostgreSQL. `upgrade --apply` now stops its
index step cooperatively, waits for other writers, and publishes at most one
generation per run. The toolchain moves to Rust 1.99.0.

## Index liveness and the CLI admin hang

`cartograph admin index` (and other generated `admin` commands that start a
background job) could rarely hang forever while holding the project's index
lease. The indexer supervisor polled pipeline work inline. The CLI's 100 ms
status poll, a pending progress write, and the monitor's progress read could
then deadlock on the shared progress lock, and the CLI's own deadline sat
inside that unbounded status call. The same inline polling let long synchronous
sections delay lease heartbeats for 30 to 50 seconds on large projects.

- Pipeline work and lease renewal now run as separate tasks, monitored from
  the supervisor's own task, so a long synchronous section cannot delay the
  heartbeat. An in-flight heartbeat verdict, cancellation, the work deadline,
  and a progress stall still take precedence over work completion, as before.
- Whole-graph sections of the spilled resolver run under `block_in_place`.
- Cancelled work that is still inside a synchronous section is awaited up to
  the operation's reap ceiling. Meanwhile the lease keeps being renewed when
  cleanup can still follow. The normal owned cleanup then runs with the real
  failure reason.
- The generated `admin` command's ten-minute CLI deadline now bounds every
  status poll. When the deadline elapses or the wait fails, the command cancels
  the job and waits up to four minutes for its cleanup before exiting nonzero.

## Lease contention is `lease_busy`, and the primary failure stays primary

An index started while another writer held the project lease or project lock
could fail as `index_cleanup_failed` with `previous_generation_visible:
false`, although the previous generation stayed current.

- Another live project lease, or a project lock still held after the bounded
  five-second staging-recovery wait, now returns the retryable `lease_busy`
  before any generation is reserved. An unchanged checkout still returns its
  no-op report.
- A writer that takes the lease or the project lock after that check is still
  refused at lease acquisition with `lease_busy`. The attempt fails its own
  reservation if it gets the project lock within five seconds. Otherwise the
  reservation stays `staging`, never current, until the next index that finds
  the project free fails it.
- In the `index --format json` failure object, `code` is always the failure
  that ended the attempt. A new `cleanup_failure` object (`code:
  index_cleanup_failed`, `message`) reports a cleanup that also failed instead
  of replacing `code`; the next index retries that cleanup.
  `code: index_cleanup_failed` on its own now means only that the
  pre-reservation staging recovery failed for a reason other than contention.
- `lease_failed` means the attempt could not establish, keep, or confirm
  ownership of its own lease: a lease acquisition that failed for a reason
  other than contention, or a lost or unconfirmed heartbeat.
- Because contention now surfaces as `lease_busy`, MCP auto-sync schedules
  its short retry for it instead of counting it toward the persistent-failure
  circuit, and `lastErrorCode` keeps the primary failure's code.

## `previous_generation_visible` is observed, and may be `null`

`previous_generation_visible` in the `index --format json` failure object used
to be inferred from the kind of error. It is now read from PostgreSQL after the
failure, within a 5-second bound:

- `true`: the project has a current published generation. That includes a
  generation this request itself published before a later step failed.
- `false`: the project has no current generation, for example before its first
  successful index.
- `null`: the bounded lookup failed or timed out.

The field is now nullable. Parsers that required a boolean must accept `null`.

## Cooperative cancellation for `cartograph index`

`cartograph index` treats its first SIGINT or SIGTERM (Ctrl-C on Windows) as a
cooperative stop. It fails its unpublished staging generation, releases its
lease, and exits nonzero with `request_cancelled`. The prepare transaction
checks for cancellation between statements, so it stops after the statement
in flight instead of running its remaining COPY, derived-relation, evidence,
and `ANALYZE` statements. A second interrupt exits immediately.

`request_cancelled` stays the primary code. The failure adds `cleanup_failure`
unless PostgreSQL confirms that every generation this request reserved left
`staging`/`ready` and that the project's index lease names none of them.
Another writer's lease or staging generation does not count against the
request. An interrupt that arrives after publication leaves that generation
current. The index then reports `request_cancelled` when the interrupt stopped
its post-publication recheck or the recheck found a change, and success when
the recheck had already matched.

## `upgrade --apply` index step

The upgrade used to run `cartograph index` under a 30-minute timeout that
killed the child, leaving its lease live until the TTL and its staging
generation abandoned. When the run's inherited exclusions changed the admitted
file set, its post-publication rescan, which applied only the request's own
exclusions, reported a change after publication, so the step kept rebuilding.

- The index step is a supervised child that reports progress. The step stops
  only after 15 minutes without progress, or at an absolute 180-minute ceiling
  (a 30-minute writer wait plus a 150-minute allowance for one generation
  build). To stop the child, the parent closes its stdin. The child then
  cancels cooperatively, and the parent kills it only after a further
  4 minutes.
- Another live writer, such as an MCP server's auto-sync, is awaited for up to
  30 minutes, including one that starts while the child scans the checkout.
  A `lease_busy` that no live lease explains is retried after a pause that
  grows from 15 seconds to 4 minutes. If the project stays busy,
  `projectReconciliation.index.state` is `another_writer_active` (`reason:
  lease_busy`, `retryable: true`).
- One publication per run: when the checkout changes after the child
  publishes, the step reports `source_changed` instead of rebuilding.
  `completed: true` no longer requires a fresh index. `projectReconciliation`
  reports each step's state, including `timed_out` (`reason: no_progress` or
  `ceiling`) and `not_run`, plus `retryable`.
- The child's cancellation proof covers only its own reservations, so another
  writer's lease or generation no longer turns a clean stop into a failure.
- `install` stops before installing Git hooks whenever its initial index
  returns a failure, including `request_cancelled` after an interrupt, in
  either output format. An interrupt that arrives after the index has
  published and matched the checkout still ends in success, and install
  continues.

These bounds apply when the binary that starts `upgrade --apply` contains them.
An upgrade started from an older release uses that release's index
orchestration until it is rerun from v2.1.35.

## Rust 1.99.0

The pinned toolchain, the workspace and facade `rust-version`, the cargo-deny
toolchain, and the `rust:1.99.0-trixie` build images (pinned by per-platform
digest) move to Rust 1.99.0. See the
[2026-10-02 dependency update](../v2/DEPENDENCY-UPDATE-2026-10-02.md). The
parse-cache fingerprint includes the toolchain, so existing parse-cache
entries no longer match and are refilled by the next index that parses those
files; an unchanged no-op index does not reparse.

The code adopts newer standard-library APIs: `floor_char_boundary` and
`ceil_char_boundary`, `str::strip_circumfix`, `bool::ok_or`, `array_windows`
and `is_sorted_by`, `String::from_utf8_lossy_owned`, `cfg_select!`, and, in
tests, `assert_matches!`. Each change is behavior-preserving and has no
user-visible effect.

## Compatibility

The PostgreSQL schema remains **45**, the generation contract remains **V18**,
and the supported ParadeDB service remains **0.25.11**. No database upgrade is
needed from v2.1.34; run `cartograph upgrade --apply --project-path <PATH>`
to install the release and reconcile each project.

Automation that parses `index --format json` failures should accept a `null`
`previous_generation_visible`. It should also read an optional
`cleanup_failure` object and treat `lease_busy` as retryable contention.

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

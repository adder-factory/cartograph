# Cartograph v2.1.35

Cartograph v2.1.35 fixes a rare CLI admin index hang, separates lease contention from cleanup failures, and moves to Rust 1.99.0.

## Changes

- Pipeline work and lease heartbeats run as separate tasks, fixing a rare `cartograph admin index` deadlock and delayed heartbeats on large projects. The CLI deadline now bounds every status poll.
- Contention with another writer returns retryable `lease_busy` instead of `index_cleanup_failed`. A secondary cleanup failure is reported separately as `cleanup_failure` (MCP: `cleanupFailure`, `lastCleanupFailureCode`).
- `previous_generation_visible` is now read from PostgreSQL and may be `null`. `cartograph index` treats the first SIGINT/SIGTERM as a cooperative stop ending in `request_cancelled`.
- `sync-if-dirty` waits up to five minutes for every live project writer. `upgrade --apply` supervises its index step by progress, waits for other writers, and publishes at most one generation.
- Rust toolchain and build images move to 1.99.0; parse-cache entries refill on the next index. New Unix-only dependency: `signal-hook` 0.4.4. See the [dependency update](https://github.com/adder-factory/cartograph/blob/main/docs/v2/DEPENDENCY-UPDATE-2026-10-02.md).

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`; no database upgrade is needed, and the new index-step bounds apply only when the upgrade is started from v2.1.35. Automation parsing `index --format json` should accept `null` `previous_generation_visible`, read `cleanup_failure`, and retry on `lease_busy`.

**Compatibility:** schema 45 (unchanged) · contract V18 (unchanged) · ParadeDB 0.25.11 (unchanged).

# Cartograph v2.1.18

Cartograph v2.1.18 makes file-level indexing failures actionable by naming the failed file and a specific reason instead of `parse_failed`.

## Changes

- Parse failures keep the project-relative path and a distinct reason, such as source drift, read failure, grammar mismatch, parser stop, nesting limits, or capacity (#137).
- `cartograph index <path> --format json` exits nonzero with `error.file_failure` (`path`, `reason`, `description`) on stderr; MCP admin job status reports the same as `fileFailure`.
- The failed generation never publishes; the existing current generation stays queryable while the file is fixed or ignored.
- Only the relative path and an allowlisted reason are reported; source text, absolute roots, database URLs, and credentials are never included.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH> --json` and require `completed: true`. Restart the agent host only when the report says `restartRequired: true`.

**Compatibility:** schema 38 (unchanged) · contract V14 (unchanged) · native Rust, PostgreSQL-only; release archives bundle no database or container image.

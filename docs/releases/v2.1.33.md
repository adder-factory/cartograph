# Cartograph v2.1.33

Cartograph v2.1.33 keeps retention ahead of failed indexing, speeds up BM25 search and status, adds opt-in Jev features, and requires ParadeDB 0.25.11.

## Changes

- Retention drains in key order and defers slow generation-row deletes (`parent_delete_deferred`); automatic indexing defers with retryable `retention_backlog`. Failed generations had filled volumes to 181 GB.
- BM25 top-K search drops from 2.7 s to about 10 ms on a 41.7K-document generation. Schema 45 stores fact counts, so status and freshness stop recounting tables.
- Unchanged explicit re-indexes reuse stored Git history (`reused: true`); `cartograph history --mode refresh` forces a rescan. `db compact` selects indexes by measured reclaimable space.
- New managed containers cap WAL (`max_wal_size=2GB`, `wal_compression=lz4`). Status reports `postgres_settings`, `doctor` warns when outdated, and `cartograph db upgrade` replaces the container.
- Opt-in Jev `features` via `--jev-features explore,context,roles,rename`. Dead-code now counts type and field usage (candidates 2,853 to 1,056); root-level `tests/` counts as test code.
- `pg_search` 0.25.11 fixes a crash when a search scan is cancelled. See the [dependency audit](https://github.com/adder-factory/cartograph/blob/main/docs/v2/DEPENDENCY-UPDATE-2026-10-01.md).

## Upgrade

An existing 0.25.10 service needs a coordinated database upgrade: run `cartograph upgrade --apply --project-path <PATH> --json`; if it reports `upgrade-managed-database`, follow its backup and confirmed replacement steps, then rerun until `completed: true`. External administrators must install `pg_search` 0.25.11 exactly; reopen MCP hosts when required.

**Compatibility:** schema 45 · contract V18 (unchanged) · `pg_search` 0.25.11 (exact); managed image PostgreSQL 18.6, pgvector 0.8.4.

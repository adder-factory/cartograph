# Cartograph v2.1.29

Cartograph v2.1.29 upgrades the supported ParadeDB search runtime to **0.25.7**
and extends managed-database upgrade recovery coverage from the immediately
preceding supported version, **0.25.6**.

## Search runtime

The managed PostgreSQL image is pinned to ParadeDB **0.25.7** by its immutable
multi-architecture manifest digest. Both Linux amd64 and arm64 images contain
PostgreSQL **18.6**, `pg_search` **0.25.7**, and pgvector **0.8.4**. External
PostgreSQL still requires version **18.4 or newer within major version 18**,
`pg_search` **0.25.7**, and pgvector **0.8.4 or newer**; pgvector **0.8.6** remains
the external-service recommendation.

ParadeDB 0.25.7 includes query-planning and execution fixes for joins, NULL
handling, and DISTINCT, improvements to deferred field fetching, and bounds
for Docker auto-tuning on large hosts. These upstream changes do not imply a
measured Cartograph performance improvement. Cartograph retains its bounded
managed resource policy, generation-local BM25 ranking, code tokenizer, and
stable result tie-breaking.

## Database upgrade and recovery

This release keeps Cartograph schema **42** and generation digest **V16**.
Earlier Cartograph migration checksums are unchanged. The supported
`pg_search` version is exact, so the Cartograph executable and database
extension must be upgraded together.

Start with the resumable project upgrade:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

If reconciliation requests a managed-database upgrade, create and verify the
reported backup, ensure sufficient free space, quiesce project writers, and
run the reported, explicitly confirmed `db upgrade` operation. Resume the
same project upgrade command and require `completed: true`.

Managed recovery tests cover both **0.25.3 → 0.25.7** and
**0.25.6 → 0.25.7**, including backup, interruption between container rename
and replacement, failure before extension catalog mutation, failure after
catalog mutation, preservation of existing data and BM25 queries, and a
repeated successful upgrade reporting a no-op. Once extension catalog mutation
has been attempted, recovery retains the new image and keeps the old
container stopped. Resume the same confirmed command; do not manually start
the old container against the possibly newer catalog.

Reopen agent hosts when required and verify fresh status plus a real indexed
query. An already attached MCP process cannot hot-load the new executable.

Cartograph remains a native Rust, PostgreSQL-only executable. Native archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

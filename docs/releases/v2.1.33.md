# Cartograph v2.1.33

Cartograph v2.1.33 keeps generation retention ahead of repeated index
failures, makes BM25 search and project status much faster, adds opt-in Jev
ranking, role classification, and rename triage, fixes dead-code false
positives, caps managed WAL, and advances the supported ParadeDB service to
0.25.11.

## Retention keeps up with failed indexing

Failed generations previously accumulated faster than retention removed them.
On busy projects this filled the managed Docker volume: two observed schemas
held 181 GB and 98 GB, almost entirely rows of 516 and 394 failed generations.

- Each large relation drains in key order and resumes after the last deleted
  key. Earlier batches re-walked every dead tuple left by previous batches,
  which grew quadratically and ended in repeated `batch-deadline` failures.
- The final generation-row delete runs inside a savepoint with its own
  deadline. A slow cascade check now defers only that row
  (`parent_delete_deferred`) instead of rolling back the batch's progress and
  leaving the generation `retiring` indefinitely.
- Automatic indexing drains failed and retiring generations before reserving
  a new one, and defers with the retryable `retention_backlog` outcome while
  cleanup is still progressing. A backlog that cannot make progress never
  blocks automatic indexing.

## Faster search, status, and re-indexing

- **BM25:** all-field search no longer evaluates per-field matches in the
  select list, which forced ParadeDB into a sequential fallback. Top-K search
  on a 41.7K-document generation drops from 2.7 s to about 10 ms. Per-field
  provenance is probed only for the returned rows.
- **Status and freshness:** schema **45** stores each ready generation's exact
  fact counts and source bytes. Status, freshness, and storage summaries read
  them instead of counting six fact tables on every call (0.3–2.5 s per call
  on a 41.7K-symbol project). Older generations fall back to counting until
  the next unchanged index backfills them once.
- **Git history:** an explicit index reuses stored churn and co-change
  evidence when HEAD, history depth, bounds, and enabled channels are
  unchanged, and reports `reused: true`. `cartograph history --mode refresh` always
  rescans. An unchanged re-index of this repository drops from about 7 s to
  2–4 s.
- **Compaction:** `db compact` selects B-tree indexes by measured reclaimable
  space (with `pgstattuple`) and estimates heap reclaim from live tuples at
  the table fill factor, so repeated runs no longer rebuild healthy indexes
  or freshly rewritten tables. Plans report `estimatedReclaimableBytes` and
  `reclaimMeasured`.

## Managed database WAL

New managed containers use `max_wal_size=2GB`, `min_wal_size=256MB`, and
`wal_compression=lz4`; idle projects previously retained up to 4 GB of WAL
each. Managed status reports `postgres_settings: current | outdated | absent`,
`doctor` warns about outdated settings, and `cartograph db upgrade` replaces an
outdated container on the same data volume through the existing
rollback-protected path.

## Opt-in Jev features

The Jev decision tier gains a `features` list. Without it only exploration
consults Jev, so existing configurations keep their disclosure scope. Enable
more with, for example,
`cartograph llm setup --preset jev --jev-features explore,context,roles,rename`.

- **explore:** each provider round judges every unread candidate, reads the
  relevant ones together, and finishes once source sufficiency reaches 0.85.
  The local cross-encoder is skipped while Jev ranks (3.6 s to 2.0 s on the
  local evaluation, same target coverage).
- **context:** one request ranks up to 24 retrieval candidates from the task
  text and their names, kinds, paths, and lines; indexed source is never sent.
  Items report `decision_relevance` and `decision_rank`. A provider failure
  falls back to the configured reranker.
- **roles:** structural rules now classify test modules, data declarations,
  handlers, and exports, cutting `unknown` roles from 61% to 25% without any
  model. With Jev, the rest are classified from metadata (name, kind, path,
  language, signature up to 160 bytes, export flag) at 0.6 probability or
  above, leaving 9.5% unknown. Model-judged roles are never downgraded by a
  rules-only sweep.
- **rename:** `propose_rename` labels textual mentions that refer to other
  symbols as `likely_other`, sending each mention's path, line, enclosing
  symbol, and up to 200 bytes of its source line. Other mentions keep
  `textual_review_required`.

Jev remains optional and uses the user's environment-based credentials.
Provider failures preserve native results with an explicit outcome.

## Fixes

- **Dead code:** type, return, and field-access usage now counts, and Rust
  `tests` modules and `tests.rs` files join the test exemption. Candidates on
  this repository fall from 2,853 to 1,056.
- **Test paths:** a root-level `tests/` directory is recognised as test code.
- **Configuration:** a second configuration writer waits up to 2 s for a slow
  durable write instead of 250 ms, so legitimate concurrent updates no longer
  fail as concurrent changes under disk or CPU pressure.

## ParadeDB compatibility and upgrade

The exact supported `pg_search` version and managed image advance from
**0.25.10 to 0.25.11**, which fixes a crash when a search scan is cancelled or
terminated. The pinned multi-architecture image contains PostgreSQL **18.6**
and pgvector **0.8.4**. The PostgreSQL schema advances to **45**; the generation
contract remains **V18**. See the [dependency audit](../v2/DEPENDENCY-UPDATE-2026-10-01.md).

An existing 0.25.10 service requires a coordinated database upgrade before the
new binary can use it. Start with the resumable upgrade operation:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

If it reports `upgrade-managed-database`, follow its backup and exact confirmed
replacement instructions, then rerun the same command. Require
`completed: true`, a fresh status, and a real query. The same replacement
applies the new WAL settings. External PostgreSQL administrators must update
`pg_search` to the exact supported version. Attached MCP processes cannot
hot-load the new binary; reopen the host when required. See the
[upgrade guidance](../TROUBLESHOOTING.md).

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

# Cartograph v2.1.36

Cartograph v2.1.36 records Rust references inside macro arguments, so items
used only in `format!`, `assert_eq!`, and similar macros are no longer
reported as unused and keep their call edges. A SCIP import whose overlay
restore fails no longer loses the failure, cancellation, or cleanup outcome of
its forced index. Debug output of parsed commands never prints a database URL
or credential-helper argument.

## Rust references inside macro arguments

Tree-sitter keeps a macro's arguments as an opaque token tree. The Rust
extractor read only the macro name and qualified or receiver calls inside it,
so unqualified calls, non-call paths, and format-string captures were
invisible. A `pub const` or function used only inside `format!(..)` or
`assert_eq!(..)` was reported as `unused_export`, and its call edges were
missing from the graph.

The extractor now records, inside macro arguments, what it records for the
same code outside a macro:

- unqualified calls such as `compute(x)`, qualified calls such as
  `a::b(..)`, `crate::`, `self::`, and `super::` paths, and receiver calls;
- qualified paths that are not calls, such as `module::LIMIT` and
  `Self::LIMIT`;
- nested macros, as macro calls;
- in the standard formatting and assertion macros (`format!`, `print!`,
  `println!`, `eprint!`, `eprintln!`, `write!`, `writeln!`, `panic!`, the
  `assert` family, `unreachable!`, `todo!`, `unimplemented!`, and
  `format_args!`), inline captures such as `{LIMIT}` and `{value:WIDTH$}`, and
  constant-shaped arguments. Escaped braces, positional arguments, raw and byte
  strings, and `name = value` arguments are handled.

The pattern of `matches!`, `assert_matches!`, and `debug_assert_matches!`
publishes what a `match` arm publishes. A qualified tuple-struct or variant
pattern such as `Shape::Circle(r)` is a path reference rather than a call,
a single-segment pattern such as `Some(r)` publishes nothing, and the `if`
guard is an ordinary expression. `Fn(..)`, `FnMut(..)`, and `FnOnce(..)` type
sugar is never a call. Inside other macros, whose syntax Cartograph cannot
know, a call-shaped token such as `Variant(x)` is still recorded as a call.

Attribute bodies, nested `macro_rules!` definitions, `$` metavariables, `#`
interpolations, lifetimes, keywords, and plain string text produce no
references. Bare constant-shaped tokens are recorded only in the standard
formatting macros, because inside data macros such as `json!` they would
inflate fan-out compared with the same code written without a macro.

One macro call may now produce up to 8,192 references instead of 1,024. Across
the 55,866 Rust files of a local crates.io cache, 95 macro calls produce
between 1,025 and 2,204 references; the old bound would have failed those
files. A macro beyond the new bound still fails closed with the same
output-limit error.

On Cartograph's own source, resolved references rise by about 7 percent with
no measurable change in index time.

The generation contract moves to **V19**. After the upgrade, an unchanged
checkout reports `fresh: false`, and the next index publishes a replacement
with the new references. `cartograph upgrade --apply` does this when it
reconciles each project.

## SCIP import keeps the index failure when the overlay restore fails

A SCIP import installs the requested artifact at
`.cartograph/scip/overlay.scip` and forces an index. When that index fails or
is cancelled, the import restores the previous overlay. If the restore failed
as well, the restore error replaced the index failure. A cancelled import then
ended as `failed` without the PostgreSQL cleanup check, and a failed index lost
its cleanup outcome.

- The admin job (MCP `scip-import`, CLI `admin scip-import`) keeps its
  `failure`, or its `cancelled` status, and any `cleanupFailure`.
- A failed restore is reported beside them as a new optional
  `overlayRollbackFailure` object (`code: scip_overlay_rollback_failed`,
  `message`). Nothing retries the restore, so the requested artifact may still
  be installed and the next index would use it. See
  [Troubleshooting](../TROUBLESHOOTING.md#scip-import-reports-overlayrollbackfailure).
- Index options are validated before the overlay is installed, so no early
  return can skip the restore.

## No secrets in Debug output

The derived `Debug` output of a parsed command line included `llm install
--database-url`, every `llm setup --api-key-arg` value, and `llm setup`'s
`--endpoint` and CLI bridge `--arg` values verbatim. Nothing printed it, so no
secret leaked, but the derive was a latent risk. Those arguments, a generated
tool invocation's argument values and project path, and a backend process
record's command line now print redacted or as counts. Tests fail if any of
them prints a secret.

The last 20 test assertions written as `assert!(matches!(..))` now use
`assert_matches!`, so a failing assertion prints the value it saw.

## Compatibility

Schema **46** admits generation contract **V19** for Rust references inside
macro arguments. Migrations 1–45 and their checksums remain unchanged. The
supported ParadeDB service remains **0.25.11**, so no database service upgrade
is needed from v2.1.35. Existing V18 indexes must rebuild once even when source
bytes have not changed. After that publication, unchanged indexing is a no-op.
Run `cartograph upgrade --apply --project-path <PATH>` to install the release,
migrate the schema, and publish each project's replacement generation.

Admin job status gains the optional `overlayRollbackFailure` object; every
existing field is unchanged.

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

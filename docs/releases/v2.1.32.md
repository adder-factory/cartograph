# Cartograph v2.1.32

Cartograph v2.1.32 improves automatic index recovery, makes Jev navigation use
the source already retrieved, fixes compact exploration and graph direction
metadata, and advances the supported ParadeDB service to 0.25.10.

## Automatic index recovery

Source edits during indexing and contention with another live index writer
now schedule bounded retries after 2–30 seconds. A retry timer also runs when
no further filesystem event arrives, so releasing a competing writer does not
require another edit to trigger recovery.

These temporary interruptions have separate accounting from persistent
failures. Repeated persistent and capacity failures retain their bounded
suppression behavior. Publication remains atomic and generation-fenced; a
failed attempt preserves the previous published generation, and stale source
is still reported explicitly until a complete current generation publishes.

## Jev and exploration fixes

- **#164:** Jev receives bounded native source windows in its initial state
  and evaluates evidence sufficiency against them. Complete supplied symbol
  windows are excluded from redundant read actions. Navigation source windows
  continue to represent additional evidence.
- **#165:** Candidates include generation-fenced symbol kinds and line ranges.
  Caller/callee operations are offered only for functions and methods.
- **#166:** `--low-tokens` returns at most eight compact evidence rows within a
  16 KiB evidence budget, without source excerpts, duplicated retrieval items,
  or decision-provider calls. Omission counts and the distinct
  `low_tokens_requested` outcome remain visible.
- **#167:** Missing Jev credentials identify the configured environment
  variable while retaining the model and endpoint in smoke diagnostics. Secret
  values are never included in those diagnostics.
- **#168:** Graph hops expose stored edge source and target IDs separately
  from traversal order, making incoming edges unambiguous in full and compact
  responses.

Jev remains optional and uses the user's environment-based credentials. Its
seven-operation and thirty-second navigation limits are unchanged. Provider
failures retain native evidence with an explicit outcome; source changes and
cancellation remain failures. Embeddings and reranking keep their existing
roles.

## ParadeDB compatibility and upgrade

The exact supported `pg_search` version and managed image advance from
**0.25.9 to 0.25.10**. The pinned multi-architecture image contains PostgreSQL
**18.6** and pgvector **0.8.4**. Runtime capability checks, Compose, CI, managed
upgrade recovery, and documentation use the same version and image digest.
The PostgreSQL schema remains **44** and the generation contract remains
**V18**.

An existing 0.25.9 service requires a coordinated database upgrade before the
new binary can use it. Start with the resumable upgrade operation:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

If it reports `upgrade-managed-database`, follow its backup and exact confirmed
replacement instructions, then rerun the same command. Require
`completed: true`, a fresh status, and a real query. External PostgreSQL
administrators must update `pg_search` to the exact supported version.
Attached MCP processes cannot hot-load the new binary; reopen the host when
required. See the [upgrade guidance](../TROUBLESHOOTING.md).

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

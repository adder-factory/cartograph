# Cartograph v2.1.40

Cartograph v2.1.40 restores the per-file extraction that v1 had for every language and checks it against v1's real output.

## Changes

- Dedicated extraction families replace the generic walker for PHP, Pascal/Delphi (including `.dfm`/`.fmx` forms), Objective-C, Swift, Dart, F#, ArkTS, Ruby, Lua/Luau, R, Nix, Clojure, Common Lisp, Lean, ReScript, Solidity, VB.NET, Apex and HCL/Terraform. Astro, Vue and Svelte scripts run through the JavaScript/TypeScript walker, and TypeScript/JavaScript, Python, Go, Rust, JVM and .NET extraction regain v1's structural facts, including Spring and MyBatis bindings and Symfony attribute routes.
- An exact v1 parity oracle checks every v1 language mode against facts captured from the v1.1.33 binary; each remaining difference is recorded as pending (planned for the next two releases) or intentional, with evidence.
- React Native and Expo bridge exports belong to the module or class that declares them; `import('./x').then(...)` no longer binds `Promise.then`; Julia short-form functions, Dart named factories and constructors, and PHP `private`/`protected` member calls resolve correctly.
- Credential-bearing literals (URLs with passwords, sensitive query parameters, provider keys) are never stored in symbol names, signatures, docstrings, references or search text, for every language family.
- Deeply nested JavaScript destructuring no longer overflows the stack, and several extractors that scanned quadratically on adversarial input are now linear and cancellable.
- `cartograph export --kind union` works, and on a stale index `export` points to `cartograph index`.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`; it migrates the schema and publishes each project's replacement generation. Existing V20 indexes rebuild once even when source is unchanged; no database service upgrade is needed from v2.1.39.

**Compatibility:** schema 48 · contract V21 · ParadeDB 0.26.0, pgvector 0.8.6 (unchanged).

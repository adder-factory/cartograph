# Cartograph v2.1.34

Cartograph v2.1.34 lets fully embedded large projects re-index again, keeps
MCP registrations that launch Cartograph through a wrapper intact during
upgrades, adds a command-based credential source for remote LLM tiers, and
stops `doctor` from blocking on an optional tier whose key is only missing
from the current shell.

## Re-indexing fully embedded large projects

Publishing a new generation carries every unchanged document's embedding
forward. That carry ran as one statement, and each carried row also enters the
model's HNSW index at roughly a millisecond. On a project with about 330,000
embedded documents the statement needed around six and a half minutes against
the three-minute prepare statement timeout, so every full re-index failed at
publication and the previous generation stayed current but stale.

The carry now walks the new generation's documents in pages of 4,096 and
reports prepare progress after each page, so each statement takes seconds and
the supervisor's deadline measures stalls rather than corpus size. The carried
set is unchanged: only documents whose path, language, kind, name, code, and
text are identical keep their vectors, and only for active models.

## Wrapped MCP registrations survive upgrades (#172)

`cartograph upgrade --apply` used to treat any registration whose command was
not the Cartograph executable as a stale pin and reinstall it. That dropped
wrapper launchers (`/usr/bin/env`, secret-manager and `direnv` commands),
their arguments, and keys such as `env` and `cwd`; when the wrapper supplied
the Jev key, Jev silently fell back to native retrieval.

- A registration is a direct pin only when its command is a Cartograph
  executable. A command whose arguments launch Cartograph's `serve` is
  `wrapped`; any other command is `custom_command` and is never repaired.
- A stale wrapped registration has only its embedded Cartograph path replaced
  in place. When that is not safe, upgrade reports a manual step instead.
- Install merges into an existing entry for the JSON hosts and edits Codex
  TOML in place, keeping `env`, `cwd`, unknown keys, and extra arguments.
- The upgrade report lists every repair with its target, location, field, and
  old and new command. Wrapper arguments and `env` values are never printed.

## Command-based LLM credentials (#173)

Remote LLM tiers can take their key from a command instead of an environment
variable, so an MCP host can launch a plain `cartograph serve` without a
secret in its config or a wrapper around the server:

```sh
cartograph llm setup --preset jev --api-key-command /path/to/secret-helper \
  --api-key-arg get --api-key-arg typesafe-api-key
```

- The command runs directly, without a shell, on the tier's first request in
  the serving process, never when configuration loads. It is bounded to 10
  seconds and 4 KiB of output; stderr is discarded.
- The key is cached in memory only. After a 401 or 403 the command runs once
  more, so a rotated key is picked up without a restart; such re-runs and
  failed runs are each limited to one every 30 seconds.
- Like a CLI-bridge command, `apiKeyCommand` is trusted project configuration:
  Cartograph and `doctor` run the program `.cartograph/config.json` names, so
  review that file before using a checkout you do not trust.
- Configuration stores only the argument vector. `apiKeyCommand` is mutually
  exclusive with `apiKeyEnv` and inline keys, and the MCP admin `llm-apply`
  action accepts it as `apiKeyCommand`.
- A failure affects only that tier. Jev reports `credential_unavailable`, names
  the program and exit status but never its output, and falls back to native
  retrieval; every other tool keeps working.

## Doctor and optional LLM tiers (#174)

A configured optional tier (Jev, summarize, ask, classify, local chat, or the
reranker) whose `apiKeyEnv` variable is not set in the shell running `doctor`
is now a warning that names the configured variable and notes that the MCP
server needs it in its own environment. It no longer makes doctor or
onboarding report "not ready". Invalid tier configuration, and a required tier
without its credential, still fail. Fix hints use the configured variable or
command, and `doctor` runs a configured credential command once, bounded,
reporting only whether it succeeded.

## Compatibility

The PostgreSQL schema remains **45**, the generation contract remains **V18**,
and the supported ParadeDB service remains **0.25.11**. No database upgrade is
needed from v2.1.33; run `cartograph upgrade --apply --project-path <PATH>`
to install the release and reconcile each project.

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

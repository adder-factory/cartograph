# Cartograph v2.1.11

Cartograph v2.1.11 adds a PostgreSQL-backed streaming pipeline for large generations and removes two parser hot spots (#117).

## Changes

- New `generationStorage` setting (`auto`, `memory`, `postgres`). `auto` spills to PostgreSQL at 10,000 files, 64 MiB of source, or a projected generation-limit hit.
- Spill indexing uses bounded batches, 1 MiB `COPY` chunks, and partitioned canonical reduction; the generation stays invisible until every check passes.
- Long Resolve work reports progress; a genuine stall reports a stable code such as `resolve_progress_stalled` in CLI, MCP admin, and auto-sync output.
- Parse workers reuse one extractor per language: the cold parse of a 14,693-file VS Code checkout took 23 s instead of about 2 min 50 s.
- Migration 36 admits contract V13 for corrected TypeScript/JavaScript construction references; V12 generations become stale until re-indexed.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>` to apply migrations 32–36 in order. `auto` needs no configuration change; check database capacity before raising `maxSpillBytes`, which counts logical payload only.

**Compatibility:** schema 36 · contract V13 · PostgreSQL 18, `pg_search` 0.25.0, pgvector 0.8.4+.

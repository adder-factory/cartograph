# Cartograph v2.1.37

Cartograph v2.1.37 fixes schema migrations stalling under lock contention and full rebuilds of large projects failing in the `reduce` stage.

## Changes

- Each migration attempt waits at most 2 seconds for a lock and retries for about 5 minutes, so readers no longer queue behind a migration for 60 seconds.
- A schema that stays busy reports the new retryable `schema_busy`: `cartograph db start` exits 75, and `upgrade --apply` reports `another_writer_active` with `reason: schema_busy`.
- The reduce stage refreshes planner statistics on spill and canonical tables, fixing `reduce_failed` on large full rebuilds; one 7,075-file project now publishes in under three minutes.
- A reduce statement timeout now reports `reduce_deadline_exceeded`. A failed index whose spill cleanup outlasts its deadline still releases its lease.
- `cartograph install` stops when the managed database start fails, and `doctor --fix` names a busy schema as the cause.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`; no database upgrade is needed from v2.1.36. If the schema stays busy, restart or stop the other Cartograph process and rerun; automation can retry `db start` on exit status 75.

**Compatibility:** schema 46 (unchanged) · contract V19 (unchanged) · ParadeDB 0.25.11 (unchanged).

# Cartograph v2.1.30

Cartograph v2.1.30 refreshes the native Rust dependencies and upgrades the
supported ParadeDB search runtime from **0.25.7 to 0.25.9**. It includes the
TOML editor update from Dependabot PR [#160](https://github.com/adder-factory/cartograph/pull/160).

## Dependencies

- `toml_edit` **0.25.15**, including upstream allocation improvements for TOML
  parsing and output.
- Clap **4.6.7** and rustls **0.23.45**.
- ArkTS grammar **0.3.0** and OCaml grammar **0.26.0**.
- Compatible lockfile updates for `bitflags`, `cc`, `clap_builder`,
  `clap_derive`, `clap_lex`, `smallvec`, and `tinyvec`.
- Linux build images now use the published, digest-pinned Rust **1.98.1**
  images on both architectures. The required compiler remains exactly 1.98.1.

All 86 direct registry dependencies were checked against current stable
releases. The remaining direct pins, GitHub Action commit pins, and Debian 13
runtime image digests were already current. The ABAP compatibility facade
continues to provide one shared Tree-sitter 0.27 runtime; no grammar sources are
patched. See the [dependency audit](../v2/DEPENDENCY-UPDATE-2026-09-14.md).

## Search runtime and recovery

The managed image pins ParadeDB **0.25.9** by its immutable multi-architecture
manifest digest. Its Linux amd64 and arm64 images contain PostgreSQL **18.6**,
`pg_search` **0.25.9**, and pgvector **0.8.4**. External PostgreSQL requires
**18.4 or newer within major version 18**, exactly `pg_search` **0.25.9**,
and pgvector **0.8.4 or newer**; **0.8.6** remains the external recommendation.

ParadeDB 0.25.9 adds upstream UUID join-filter improvements and JSON-path
aggregate support. These changes do not establish a measured Cartograph
performance improvement. Generation-local BM25 ranking, source-code
tokenization, stable tie-breaking, and the managed resource limits remain
part of the capability and integration gates.

Managed upgrade recovery coverage retains **0.25.3** and **0.25.6** source
images and adds the immediately preceding **0.25.7** image. It exercises
backup, interrupted container replacement, failures before and after extension
catalog mutation, retained data and BM25 queries, and repeated upgrade no-ops.
Cartograph schema **43** admits generation digest **V17**. An unchanged project
with an older generation now reports stale and rebuilds once, ensuring the new
grammars take effect. Subsequent unchanged indexing reports a no-op. Migration
checksums 1–42 remain unchanged.

Start with the resumable project upgrade:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

When reconciliation requests a managed-database upgrade, verify the reported
backup and free-space headroom, quiesce project writers, and run the reported,
explicitly confirmed `db upgrade` operation. Resume the same project upgrade
command and require `completed: true`. After extension catalog mutation has
been attempted, recovery retains the replacement image and keeps the previous
container stopped; resume the same confirmed command.

Verify fresh status and a real query after upgrading. Reopen agent hosts when
required: an attached MCP process cannot hot-load the new executable.

Cartograph remains a native Rust, PostgreSQL-only executable. Archives contain
no PostgreSQL, ParadeDB, pgvector, database, or container image. There is no
SQLite runtime, importer, optional feature, or fallback.

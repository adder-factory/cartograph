# Cartograph v2.1.31

Cartograph v2.1.31 adds optional Jev-guided code retrieval with user-supplied
credentials and refreshes the native dependencies and release build images.

## Optional Jev navigation

`cartograph explore` and `cartograph_explore` can use the pinned
`jev-1.13.0` decision model to select additional native retrieval operations.
Jev answers parallel next-action and evidence-sufficiency questions. Cartograph
executes the bounded source, symbol, caller/callee, and file-outline queries;
the calling assistant receives the evidence and writes the answer.

Enable it explicitly with an environment reference:

```sh
cartograph llm setup . --preset jev --api-key-env TYPESAFE_API_KEY
```

Supply the key in the invoking host's environment. Setup stores the variable
name, not its value, and preserves other model tiers. The configured provider
receives bounded question and repository source context; see the
[configuration guide](../CONFIGURATION.md#optional-jev-navigation).

Missing configuration or credentials, provider errors, invalid responses, and
rate limits preserve the native evidence with an explicit navigation outcome.
`--decision native`, summary requests, and low-token requests bypass Jev.
Source/generation changes and cancellation remain failures. Navigation admits
at most seven extra retrieval operations, bounded source windows and model
state, and a thirty-second navigation/freshness deadline with cooperative
cleanup. Truncation, confidence, model identity, and evidence provenance remain
visible.

Credential transport uses the pinned HTTPS endpoint, a sensitive bearer
header, no HTTP redirects, and redacted failure categories. Keys are excluded
from model request bodies, project configuration, and public debug/error output.

## Dependency and indexing compatibility

- `tree-sitter-cuda` advances from **0.21.1 to 0.21.2**, including CUDA tile
  qualifiers. `unicode-ident` advances from **1.0.24 to 1.0.26**. This preserves
  the commit ancestry of Dependabot PR [#162](https://github.com/adder-factory/cartograph/pull/162).
- Ten transitive Rust packages are updated by Cargo's resolver. All 86 direct
  registry dependencies were checked against current non-yanked stable releases.
- Linux Rust **1.98.1** build images and Debian **13 slim** smoke images use
  refreshed immutable platform digests. GitHub Action pins remain current.
- ParadeDB **0.25.9**, PostgreSQL **18**, and pgvector requirements are unchanged.

Schema **44** admits generation contract **V18** for the updated CUDA parser
and Unicode identifier semantics. Migrations 1–43 and their checksums remain
unchanged. Existing V17 indexes must rebuild once even when source bytes have
not changed. After that publication, unchanged indexing is a no-op. See the
[dependency audit](../v2/DEPENDENCY-UPDATE-2026-09-22.md).

Use the resumable project upgrade, then verify fresh status and a real query:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

Require `completed: true`. An attached MCP process cannot hot-load a new binary;
reopen the agent host after upgrading when required. No managed database image
replacement is needed for an already compatible ParadeDB 0.25.9 service.

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

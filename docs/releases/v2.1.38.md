# Cartograph v2.1.38

Cartograph v2.1.38 makes Rust turbofish calls such as `parse::<u32>(text)` and
`items.collect::<Vec<_>>()` name and resolve the function they call. Before,
the type arguments stayed in the call's name, so a free-function turbofish
call never reached its target in the call graph. Inside macro arguments, a
turbofish's commas no longer shift which argument holds a pattern or a format
string.

## Turbofish calls resolve to their function

A Rust turbofish passes explicit type arguments to a call: `f::<T>(..)`,
`module::f::<T>(..)`, or `value.f::<T>(..)`. Cartograph recorded such a call
under its full text, `f::<T>` or `module::f::<T>`. That text matches no
declared name, so the call stayed unresolved. On Cartograph's own source, 490
free-function turbofish calls were unresolved, including calls to the
project's own generic helpers. Method calls resolved through their member
name but kept the type arguments in their recorded name, and each added a
field access that a call without type arguments does not have.

- A turbofish call now records the function it calls: `f`, `module::f`, or
  `value.f`. Free-function calls resolve like any other call, and method calls
  keep resolving through their member.
- The path or member inside a called turbofish is no longer recorded a second
  time as a separate reference or field access.
- A turbofish used as a value without a call, such as `let parse = parse::<u32>;`,
  is unchanged.

## Turbofish calls inside macro arguments

Inside a macro's arguments, a turbofish's commas counted as argument
separators. In `matches!(build::<A, B>(), Shape::Circle(_))` the pattern was
then read as an expression, and in `assert!(check::<A, B>(flag), "{LIMIT}")`
the format string was missed. Turbofish calls inside macros were not recorded
at all.

- Commas inside `::<..>` type arguments no longer separate macro arguments.
  Only `::<` opens type arguments, so in `assert!(a < b, "{LIMIT}")` the bare
  `<` stays a comparison and the format string is still found.
- `f::<T>(..)` and `value.f::<T>(..)` inside macro arguments are recorded as
  calls, the same way as outside a macro. Type names inside the type
  arguments are not recorded as references, as outside a macro.

## Compatibility

Schema **47** admits generation contract **V20** for Rust turbofish calls.
Migrations 1–46 and their checksums remain unchanged. The supported ParadeDB
service remains **0.25.11**, so no database service upgrade is needed from
v2.1.37. Existing V19 indexes must rebuild once even when source bytes have
not changed. After that publication, unchanged indexing is a no-op. Run
`cartograph upgrade --apply --project-path <PATH>` to install the release,
migrate the schema, and publish each project's replacement generation.

Cartograph remains a native Rust, PostgreSQL-only executable. Release archives
contain no PostgreSQL, ParadeDB, pgvector, database, or container image. There
is no SQLite runtime, importer, optional feature, or fallback.

# Cartograph v2.1.10

Cartograph v2.1.10 fixes large native-index capacity failures with actionable error codes, correct limits, batched publication, and an opt-in larger ceiling (#117).

## Changes

- Capacity failures report stable codes such as `resolve/generation_capacity_exceeded` (CLI) and `resolve_generation_capacity_exceeded` (MCP admin jobs, auto-sync).
- New `maxGenerationBytes` setting from 1 byte to 8 GiB (default 1 GiB). Reports include resolve and validation high-water charges for sizing.
- Publication uses ordered `COPY` batches of at most 100,000 rows or 64 MiB inside one atomic transaction; long healthy publication is no longer mistaken for a stall.
- Status gives biomarker aggregation a five-second deadline and reports it unavailable instead of failing.
- Go immediately invoked function literals and Python lambdas no longer become call-target names. `ignore` updates to 0.4.32.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`. Keep the 1 GiB default and raise `maxGenerationBytes` only after a typed capacity error and a host-headroom review.

**Compatibility:** schema 31 · contract V12 · PostgreSQL 18, `pg_search` 0.25.0, pgvector 0.8.4+.

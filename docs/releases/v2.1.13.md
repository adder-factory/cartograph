# Cartograph v2.1.13

Cartograph v2.1.13 makes auto-sync catch up promptly during rapid editing and puts explicit ceilings on background work and the managed database.

## Changes

- Filesystem events go straight to the indexer. Debounce drops to 750 ms with a two-second hard deadline; a `CARTOGRAPH_WATCH_DEBOUNCE_MS` above two seconds still wins.
- A database outage no longer leaves auto-sync permanently suppressed; a capped recovery probe keeps running.
- Automatic indexing caps extraction at four workers and skips Git churn, co-change, and issue history; explicit `cartograph index` still refreshes them. Automatic retention no longer vacuums synchronously.
- New managed containers get a 2 GiB memory limit, four CPUs, 256 processes, and tuned checkpoint/WAL settings; `db status` and `doctor` report the observed values.
- ParadeDB `pg_search` moves from 0.25.0 to 0.25.1; the managed image runs PostgreSQL 18.4 with pgvector 0.8.4.

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`. Older managed containers are never recreated silently: if the report requests a managed-database upgrade, take the backup, run only the exact confirmed replacement command it prints, then repeat the upgrade.

**Compatibility:** schema 37 (unchanged) · contract V13 (unchanged) · PostgreSQL 18, `pg_search` 0.25.1, pgvector 0.8.4+ (0.8.6 recommended for external).

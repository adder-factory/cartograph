# Cartograph v2.1.42

Cartograph v2.1.42 brings the v1 parity port close to done: framework routes, native bridges and most resolution gaps left after v2.1.41, checked against v1's real output.

## Changes

- JavaScript frameworks: every Angular route object (including lazy modules), Bun.serve method maps, CLI command registrations, Express routes without a framework import, Hono and NeuG forms, and Next/SvelteKit/Nuxt file-route conventions.
- Other frameworks: ASP.NET, Spring (class base routes, property injection), Flask blueprints, Go `net/http`, Rails, Rocket, Flutter, Symfony YAML, CodeIgniter, MyBatis, Drupal routing/services/tags/hooks and Salesforce Aura and LWC.
- Native bridges: React Native, Expo, Fabric and Swift↔Objective-C bridges reach the native implementation; edges without ownership evidence are left out rather than guessed.
- Resolution: explicitly typed receivers in 14 more languages, chains through declared return types, static and inherited members, Go module imports, OCaml module paths, file-path imports and re-export aliases.
- Every new path abstains on shadowing, reassignment, overloads or unproven scope, and lets the existing resolver decide.
- Exact v1 oracles: per-file facts now have 2 pending of 8,165; cross-file facts have 95 pending of 1,724 (1,065 matched exactly or by pinned shape, 564 intentional v2 corrections).

## Upgrade

Run `cartograph upgrade --apply --project-path <PATH>`; it migrates the schema and publishes each project's replacement generation. Existing V22 indexes rebuild once even when source is unchanged; no database service upgrade is needed from v2.1.41.

**Compatibility:** schema 50 · contract V23 · ParadeDB 0.26.0, pgvector 0.8.6 (unchanged).
